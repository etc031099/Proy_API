## F.6A.6 — Corrección de contadores de riesgo

La fuente del desajuste era el adaptador LIVE de ML (`ml/service/v3_live_inventory_supplier.py`):
el motor de inventario entrega `row.risk.level` en mayúsculas (`CRITICAL`,
`HIGH`, `MEDIUM`, `LOW`), mientras la agregación comparaba directamente con
claves minúsculas. Backend y frontend ya trasladaban/renderizaban correctamente
el contrato `riskCounts.critical/high/medium/low`.

La agregación ahora normaliza el nivel estructurado y cuenta sobre las mismas
filas de inventario que alimentan el ranking. Si falta un nivel o llega uno
desconocido, los cuatro conteos permanecen `null` y aumenta
`riskUnavailableCount`; un inventario vacío produce cuatro ceros. No se
alteraron cálculo, umbrales ni etiquetas de riesgo.

Casos focales: una fila CRITICAL, dos HIGH, una MEDIUM, una LOW, inventario
vacío, normalización de mayúsculas/minúsculas, nivel ausente/desconocido y
coincidencia entre conteos y filas públicas del ranking. Los tres tests nuevos
de conteo pasan. La suite focal completa del archivo se inició, pero se detuvo
tras quedar sin progreso visible en una prueba posterior; por ello su resultado
completo no está confirmado.

El conteo LIVE exacto de producción todavía requiere publicar este cambio y
volver a cargar el dashboard. Los valores `1/2/1/1` de la fixture son de prueba,
no cifras atribuidas al negocio cloud.
