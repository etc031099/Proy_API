## Configuración y selección

`backend/.env.example` incluye únicamente ejemplos:

```dotenv
AGENT_ENABLED=false

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_REASONING_EFFORT=none
DEEPSEEK_MAX_OUTPUT_TOKENS=300
DEEPSEEK_TIMEOUT_MS=15000
```

El entorno existente sin `LLM_PROVIDER` conserva Gemini. Elegir `gemini` conserva
su adapter, modelos, clasificación y failover anteriores. Elegir `deepseek` habilita
exclusivamente síntesis GROUNDED_LLM; desactiva el fallback genérico a Gemini. Una
consulta que necesita el clasificador antiguo falla de manera controlada en lugar
de cambiar de proveedor automáticamente. No hay fallback entre proveedores.

La key del proveedor elegido se exige cuando `AGENT_ENABLED=true`. La key de Gemini
no es necesaria al elegir DeepSeek. La construcción del transporte es lazy y ocurre
solo al generar una interpretación. Deterministic/OOD no usan transporte.

URL permitida: origen HTTPS oficial, raíz o `/v1`, sin credenciales en URL, query,
fragmentos ni beta. Se rechazan redirects. Modelo configurable entre los dos
identificadores vigentes verificados; el inicial es flash. `deepseek-v4-pro` no está
seleccionado y no tiene tarifa configurada aquí. Los nombres legacy no se aceptan.
Thinking queda bloqueado en `none`; output configurable 1–300; timeout 1–20000 ms.
No se agregó SDK ni dependencia.

## Flujo, contexto y respuesta

Pregunta → gate/routing → tenant/contexto V3 validado → skills READ aprobadas →
context builder J.2A → una llamada DeepSeek → validación → interpretación.

Se reutilizan las siete skills, budgets, contratos y fechas de J.2A. El límite del
contexto sigue siendo 6400 bytes; fixtures J.2A: 1517–3418 bytes. No se envían
snapshots, toda la memoria ni respuestas completas del dashboard. La pregunta se
redacta y limita con el builder existente. Cada evidencia conserva su corte/revisión.

El request neutral exige `route=GROUNDED_LLM`. Mensajes solo system/user con role y
content; no admite herramientas, claves o parámetros extra. El system prompt pide
español, brevedad, hechos del contexto, datos faltantes explícitos y recomendaciones
separadas. Solicita JSON con observations/evidenceRefs/interpretation/
advisoryRecommendation y limitations. El adapter envía JSON output, stream=false,
max_tokens hasta 300 y reasoning_effort=none. Temperature=0 es aplicable en este
modo sin thinking; no se habilita un modo donde sea irrelevante.

Se mantienen las restricciones MA28 estadístico; HGB V3 28d rechazado; FP-Growth
asociación, sin causalidad; Isolation Forest atipicidad, sin fraude/probabilidad;
WAPE no accuracy; K-Means exploratorio, sin predicción de churn. Nuevos productos
incluyen noHistoricalSkuData=true y recomendación exploratoria, sin forecast validado.

Se cubrieron expresiones de los casos J.2B: «debería reponer ... y por qué» y
«resume ... negocio», conservando la consulta simple de reposición determinista.
Los hechos renderizados se conservan aunque falle la síntesis. El guard de J.2A
comprueba estructura, referencias, cifras y afirmaciones prohibidas; no demuestra
por sí solo toda la verdad semántica. La calidad con un proveedor real queda pendiente.

## Telemetría y costos

Se normalizan prompt_tokens → inputTokens; completion_tokens → outputTokens;
total_tokens → totalTokens. Se preservan prompt_cache_hit_tokens (o el desglose
equivalente cached_tokens), prompt_cache_miss_tokens y reasoning_tokens agregados.
Uso ausente se conserva null, sin estimación de tokens. Breakdown incoherente se
rechaza. Solo final content cruza el adapter; no se guarda reasoning_content,
headers, clave, error body ni envelope completo.

Root usage incluye provider, model, llmCalls, input/output/total, cachedInputTokens,
cacheMissInputTokens, reasoningTokens, providerLatencyMs, estimatedCostUsd,
estimatedCostRangeUsd, pricingVersions y providerFailures. Se conservan aliases
anteriores. La proyección pública permite solo estos campos. La actividad del
frontend muestra proveedor/modelo, tokens, latencia y costo o rango en USD.

`backend/src/config/deepseekPricing.js` desacopla precios del transporte:

| USD / 1M tokens | Off-peak | Peak |
| --- | ---: | ---: |
| Input cache hit | 0.003 | 0.006 |
| Input cache miss | 0.15 | 0.30 |
| Output | 0.60 | 1.20 |

Versión deepseek-flash-2026-10-15, effectiveFrom=2026-08-16 según el requisito de
esta fase. Las cifras se verificaron en la página oficial; esta página no aporta
una fecha histórica de entrada en vigor independiente. No se implementa calendario
de feriados chinos. Se devuelve estimatedCostUsd=null y un rango off-peak/peak.

Por cada extremo: `(hit × tarifaHit + miss × tarifaMiss + output × tarifaOutput) /
1000000`. Hit y miss son partes disjuntas del input; no se suman otra vez al input.
Sin breakdown completo, tarifa/modelo conocido o fecha efectiva válida: costo y
rango desconocidos. El rango no es un cargo confirmado. Ejemplo de prueba: 400 hit,
600 miss y 100 output → USD 0.0001512–0.0003024.

Deterministic/OOD sin generaciones: provider=none, llmCalls=0, tokens=0, costo=0.
Un fallo HTTP/timeout sin usage reportado deja consumo/costo desconocidos, no cero.
Una respuesta con usage válido que falla el guard mantiene los tokens reportados.

## Errores y WRITE safety

401/403, 429, timeout, red/5xx, JSON ilegible, tool calls inesperadas y respuestas
truncadas se rechazan sin reintentos. Se registra categoría segura de fallo; la
respuesta conserva hechos y comunica que no pudo validar interpretación. Rechazo
por grounding registra synthesis_finished REJECTED y request FAILED, con usage
conocido conservado. No se imprime el body del error.

DeepSeek no recibe herramientas. Una recomendación no prepara ni confirma compras.
El test integrado verifica recomendación → «hazlo» sin ejecución → preview explícito
→ READ con DeepSeek → «hazlo» solo revisa preview → cancelación, sin confirmaciones.
J.2A conserva además la confirmación explícita con ejecutor simulado.
