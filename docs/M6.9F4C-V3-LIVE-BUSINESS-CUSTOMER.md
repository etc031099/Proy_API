# M6.9F.4C — Business and Customer LIVE V3

Status: Business/Customer LIVE adapter implemented and HTTP-validated locally. No deploy, cloud requests, Atlas, or real live business data was used.

## Scope and dispatch

The ML API routes `dataMode=LIVE` Business and Customer requests through `LiveBusinessCustomerAdapter`. It consumes the already validated, immutable `LiveV3Context` produced by F.3, reuses M6.8 aggregation, segmentation, quantile, trend, and preference logic, and keeps Inventory, Supplier, Forecast, Health, and Market Basket LIVE disabled. A LIVE request without its snapshot still fails before analytics. HISTORICAL requests continue through their original handlers and retain the frozen 2026-10-12 cutoff.

The LIVE response identifies `HISTORICAL_PLUS_OPERATIONAL_SNAPSHOT`, the snapshot hash, data revision, as-of date, timezone, and adapter engine version. Health exposes a separate `liveDomains` map; only Business and Customer are marked ready.

## Effective sales and periods

The adapter combines M6.8's cached frozen sales view through 2026-10-12 with completed, uncancelled snapshot sales up to the snapshot as-of date. It maps cancellation references to stable sale codes and excludes the original sale once cancelled; it does not add a synthetic negative sale or mutate frozen records. Consumer Final remains represented by a null customer code and is excluded from individual RFM.

M6.8 period resolution gains an opt-in `allow_live` argument used only by the new adapter. Its default historical guard and clipping remain unchanged. Explicit date ranges and the existing TODAY, YESTERDAY, LAST_7_DAYS, and LAST_30_DAYS semantics are inclusive in America/Lima and may cross the cutoff. TODAY includes the partial current day through the snapshot boundary. Comparisons use the same effective sales view and equivalent preceding range.

## Costs and partial results

Historic sale costs continue to use canonical `costAtSaleCents`. LIVE sale lines contribute cost only when `costKnown=true` and `costBasis=CAPTURED`; unknown values are represented internally as a compatibility placeholder only for calling M6.8, and the adapter masks every dependent COGS/margin field, trend, and ranking before returning the result. The placeholder is never exposed as a calculated zero-cost claim. Revenue, units, tickets, and average ticket remain available. Responses carry cost line coverage and `PARTIAL` status when evidence is incomplete. LIVE monetary requests reject currencies other than PEN rather than mixing amounts or applying current FX.

## Customer semantics and cache

The customer cohort is the frozen registered cohort plus contacts visible in the validated snapshot. A newly created contact with no observed purchase is explicitly returned as `INSUFFICIENT_HISTORY` with no R/F/M scores; it is not mislabeled as inactive or given synthetic history. A first observed recent purchase is classified as NEW using the existing M6.8 rule. Recency, frequency, spend, preferences, trends, and periods use effective sales; cancelled sales no longer contribute. RFM does not include Consumer Final. Frozen product rows are copied before applying live catalog projections, so the adapter cannot mutate the historical source objects.

An adapter-local bounded cache keys derived views/results by business and snapshot identity (which includes revision/hash/as-of) and request period/filter/mode. Cached engine results are treated as immutable; bounded small result copies protect them from response shaping. A new snapshot hash cannot reuse the previous result. No authentication decision is cached.

## Validation and performance

The project venv launcher points to a missing Windows Store Python installation. Tests used the bundled Python 3.12 runtime plus the existing venv site-packages path; no repository or environment configuration was changed.

- The TestClient hang was isolated to environment sandboxing, not the app lifespan or an open app resource: even an empty FastAPI app stalled before startup while Windows asyncio created its loopback socket pair (`socket.accept` in `socket._fallback_socketpair`). Running the same local harness where that internal loopback socket is permitted entered the context, returned HTTP 200, and completed shutdown. FastAPI 0.116.1 / Starlette 0.47.3 / HTTPX 0.28.1 did not show an API incompatibility.
- F.4C HTTP harness: `with TestClient(app) as client`, with an instrumented lifespan and the existing HTTP routes. It completed response serialization and context-manager shutdown; the Python test process exited normally (no lingering thread/handle observed).
- Historical Business and Customer HTTP responses: **PASS**, as-of 2026-10-12, with no snapshot. Canonicalized response `data` exactly matches the direct `V3IntelligenceRuntime` methods; metadata source remains `CANONICAL_V3_BUNDLE`.
- LIVE Business HTTP: **PASS** for TODAY and LAST_7_DAYS. Response JSON is finite/serializable; direct-adapter parity matches after normal JSON canonicalization; unknown costs yield PARTIAL and `null` COGS/margin, never invented zero. The LIVE delta is included and no historical fallback is used.
- LIVE Customer HTTP: **PASS** with an existing customer and a newly created contact/customer. Direct-adapter parity matches; the new customer's purchase is classified NEW, unknown contribution margin remains null, and JSON is serializable.
- Cancellation HTTP: **PASS**; a valid revision-2 cancellation removes the LIVE ticket once and does not double-count it. Missing-cost HTTP: **PASS**; revenue remains available while COGS/margin is unavailable.
- Error serialization: **PASS** for missing snapshot (`LIVE_SNAPSHOT_REQUIRED`), mismatched tenant (`TENANT_MISMATCH`), and bad snapshot hash (`SNAPSHOT_HASH_MISMATCH`). LIVE Inventory, Supplier, Forecast, and Business Health all remain HTTP 501 `LIVE_ANALYTICS_NOT_READY`; readiness reports only Business and Customer LIVE-enabled.
- F.4C adapter/runtime fixtures: 14/14 PASS; HTTP focal: 5/5 PASS; F.3 live-context: 7/7 PASS; M6.8 Business/Customer/Supplier: 8/8 PASS. Combined focused regression: **37/37 PASS**. Selected V1/V2 serving contracts: **19/19 PASS**. Python compilation and `git diff --check`: PASS.
- The earlier full M6.9B serving suite was not rerun; this phase's exact historical endpoint parity was exercised by the focused HTTP test using the approved local runtime and compared against its direct methods. Full ML service suites remain outside this focused closeout.
