# M6.9H.6 — Natural-language assistant UX

## Scope

This phase adds bounded natural-language aliases and presentation behavior to the existing V3 router and entity-resolution flow. It does not add another resolver, change analytics, connect cloud services, or execute business writes.

## Validation

`backend/test/assistantNaturalLanguageH6.test.js` covers 103 semantic phrases across stock/product questions, sale and purchase parsing, category/brand queries, ambiguity/ordinal selection, follow-up context, write safety, and out-of-domain routing. Focused existing regressions also passed:

- product resolution and follow-up context: 6/6
- guided purchase/selection/cancellation: 6/6
- action-input ambiguity and preview safety: 2/2
- H.6 semantic suite: 5 test blocks passed, covering the 103 phrases plus targeted cases
- JavaScript syntax and `git diff --check`: passed

The first H.6 run exposed gaps in plural/case handling, `opcion 2`, stock follow-up, and the cancellation phrase `ya no`. These were fixed and covered by the final passing suite.

## Behavior added

- Bounded stock-query forms resolve common human terms and plural variants through the existing entity lookup. A simple stock question returns a compact stock-only response, for example `Pan francés: 21 unidades disponibles.` It does not show forecast, coverage, ABC/XYZ, risk, or price by default.
- Common category requests map to existing category/subcategory prefixes for soft drinks, cookies, milk, and bread. Brand requests recognize a small explicit set including Gloria, Inca Kola, and Coca-Cola. Results continue through the existing candidate-resolution flow; category or brand is not silently treated as a unique SKU.
- Product presentations remain separate candidates identified by their existing stable product identities. Candidate ordering remains the existing resolver’s deterministic ordering.
- A follow-up such as `esa no, la otra` may choose the other item only when the saved candidate list contains exactly two options and a product is already selected. This is a READ selection and never confirms a pending WRITE.
- Sale/purchase phrases with `quiero`/`quisiera` and bounded informal spellings feed the existing parser and preview flow. `ya no` is recognized as cancellation. No test in this phase invokes a write executor.
- Narrow typo normalization is limited to the explicitly tested forms; this is not general-purpose autocorrection.

## LLM and out-of-domain behavior

The supported H.6 business-query cases are tested through deterministic routing and entity resolution; the tests do not invoke an LLM/provider. This is not a production token-metering report. Three out-of-domain examples are explicitly left for the existing classifier/fallback (`¿Quién ganó el partido de ayer?`, `¿Cuál es la capital de Japón?`, `Escríbeme una historia`); provider calls/tokens for those paths were not measured. Full out-of-domain rejection and cost control remain outside H.6.

## Limitations

- Category and brand aliases are intentionally bounded, not exhaustive Spanish morphology or fuzzy search.
- Only stock questions have a compact response mode in this change. Price, coverage, and full-detail intent modes were not broadly redesigned.
- Brand-scoped depletion questions such as `¿cuál Coca-Cola está por acabarse?` are not validated as a brand-filtered low-stock ranking; do not treat the generic low-stock ranking as an answer to that narrower question.
- Contextual WRITE wording such as `saca 2 de la segunda` was not proven as an end-to-end guided action in this phase. Existing ordinal selection and preview/cancel safety regressions passed, but that exact multi-turn phrase remains unconfirmed.
- Clickable UI candidate rendering was not changed; existing support is reused.
- No cloud, deployment, database, sales, purchase, or stock mutation was performed.
