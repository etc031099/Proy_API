## Primera pasada, triage y fix

La primera versión exploratoria del arnés produjo discrepancias de oráculo/fixture antes de cerrar la muestra: frases que no pertenecían al contrato directo de `routeV3` (algunas se resuelven por router legado o aclaración segura), fixtures incompletos para selección/contexto y cinco expectativas con nombres internos incorrectos para `actionIntent`. No se trataron esas discrepancias como defectos del producto ni se invocó un LLM para decidirlas. Se acotó la selección a contratos soportados y se corrigieron los oráculos.

La muestra curada confirmó una discrepancia real de routing: una pregunta general por días de cobertura podía terminar como analítica de negocio. `v3Routing` ahora trata las consultas de cobertura como inventario; con un SKU consulta el detalle de ese producto, y sin producto solicita una aclaración. No cambia fórmula, etiqueta, umbral ni cálculo. Se agregaron regresiones para SKU explícito, producto ausente y continuidad con producto seleccionado. La explicación académica de cobertura conserva su ruta existente.

Después del fix, el conjunto final combinado pasó sin fallos. Los casos de forecast fuera de horizonte y de anomalías fuera del corte histórico se mantienen fail-closed con aclaración.

## Semántica ML y seguridad

La muestra y sus regresiones conservan las distinciones aprobadas:

- HGB es aprendizaje supervisado evaluado; MA28 es el método estadístico operacional V3 para 1/7/14 días. WAPE no se transforma en `accuracy = 100 - WAPE`.
- K-Means es clustering no supervisado sobre RFM; `k=4`, silhouette y ARI conservan su significado, sin probabilidades.
- Isolation Forest marca anomalías para revisión contextual; anomalía no es fraude y el score no es probabilidad.
- FP-Growth describe asociaciones observadas mediante support/confidence/lift; no demuestra causalidad y usa artifact congelado al 2026-10-12.
- Selección no confirma; preview precede a confirmación explícita; cancelación y entidades ambiguas no ejecutan acciones. No se efectuaron ventas, compras ni creación de reglas.
- Errores sin historial, métricas nulas, fechas/horizontes no admitidos y datos no disponibles conservan aclaración o error controlado; no se inventan métricas.

## Conclusión

La muestra reducida alcanzó 100% PASS, WRITE safety focal 100% PASS, semántica ML correcta y continuidad contextual sin regresión crítica. **No se recomienda ejecutar la batería de 600–800 casos** salvo que una futura señal de producción o una brecha concreta de cobertura la justifique.
