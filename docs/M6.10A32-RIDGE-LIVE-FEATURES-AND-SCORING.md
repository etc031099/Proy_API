The module receives the already validated immutable `LiveV3Context`, the canonical `V3Dataset`, explicit authenticated `business_id`/`scenario_id`, SKU, horizon, and an injected registry loader. The intended backend loader is `createForecastModelRegistryService().getActiveModelArtifact({ businessId, scenarioId, horizonDays })`; A.3.1 follows the registry pointer to the exact artifact ID/version within a consistent transaction. This phase adds no public or internal HTTP route and does not wire a public forecast request to Ridge. The callback seam keeps Mongo ownership in backend and feature engineering/scoring in Python.

```text
authenticated backend tenant + consistent snapshot
  -> exact A.3.1 active-pointer read (injected loader)
  -> validated LIVE context + frozen historical dataset

```

The existing `LiveForecastAdapter` remains MA28-only and untouched. This module never falls back to MA28.

## Feature contract

- `featureVersion`: `RIDGE_CAUSAL27_V1`
- `featureHash` (SHA-256 over canonical UTF-8 JSON of version, timezone, cutoff, target, ordered feature lists, semantic rules, history/missing rules and exclusions): `84e928e62343eb9d9b7d9e0dc8843ea8e9395ae135997287f5b7ea3a02a860f5`
- Timezone: `America/Lima`; closed origin `T` is `snapshot.metadata.observationsClosedThrough`.
- Target remains cumulative effective units sold over `T+1..T+h` for `h=7,14`.
- 29 certified dates, oldest to newest, are required: `T-28..T`.

Exact ordered features:

| # | Feature | Rule |
|---:|---|---|
| 1–6 | `sku`, `categoryCode`, `subcategoryCode`, `brand`, `presentation`, `unit` | Canonical string descriptors effective at T. |
| 7–8 | `sizeValue`, `containedUnits` | As-of catalog descriptors; finite, with containedUnits an integer. |
| 9–14 | `weekdayNext`, `monthNext`, `dayOfMonthNext`, `weekendNextDays`, `paydayDays`, `monthEndDays` | T+1 calendar fields; horizon counts over T+1..T+h. ISO weekday; payday 14–16; actual calendar month-end. |
| 15–19 | `currentUnits`, `lag_1`, `lag_7`, `lag_14`, `lag_28` | `unitsSold[T]`, `[T-1]`, `[T-7]`, `[T-14]`, `[T-28]`. |
| 20–24 | `rollingMean_7`, `rollingMean_14`, `rollingMean_28`, `rollingStd_7`, `rollingStd_28` | Closed windows ending at T; standard deviation is population `ddof=0`. |
| 25–27 | `zeroSalesStreak`, `daysSinceLastSale`, `neverSoldInObservedWindow` | Within the 29 observed days; no positive sale means 29 days and flag 1. |

The eleven A.2.3 excluded fields are not read or recreated: holiday indicators/coverage, price/promo features, stock/availability, and limited-availability counts. Synthetic latent-demand labels and stockout flags are also excluded.

### Closed-day and catalog semantics

Historical days through `2026-10-12` come only from the canonical historical dataset. Days after the cutoff come only from `LiveV3Context.closed_sales_by_product_day`, which is the certified net closed-day source; a cancellation is not subtracted a second time. A missing or partial day fails closed (`FEATURE_UNAVAILABLE` for operational delta; missing historical coverage is `INSUFFICIENT_HISTORY`). A certified zero is retained as zero. Open/current-day sales are never consulted.

Product attributes start from the frozen canonical catalog and apply only product journal entries whose timezone-aware `effectiveAtUtc` maps to a Lima local date no later than T. Post-T changes are ignored. Missing required descriptor or invalid type fails closed. No current stock, future receipt, price, or other operational state enters the row.

## Safe Ridge artifact and score

Artifact schema: `ridge-causal27-json-v1`, strict UTF-8 JSON only (no joblib/pickle). The registry envelope supplies `metadata` and raw `artifactData`; the loader checks exact tenant/scenario/horizon, `ACTIVE`, Ridge family/recipe, feature version/hash, frozen promotion-policy version/hash, byte count and SHA-256. It rejects duplicate JSON keys, extra/missing fields, wrong dimensions, unordered/duplicate categories, invalid scales, NaN/Infinity and nonfinite coefficients. Category lists encode the learned OneHotEncoder order. Parameters include scaler means/scales, coefficients/intercept, one-hot category arrays, horizon/recipe/schema and feature metadata. Maximum bytes: 5 MiB.

For each of six categorical values the scorer emits the serialized one-hot block; unseen categories emit all zeros, matching `OneHotEncoder(handle_unknown="ignore")`. Each numeric feature is transformed as `(x - mean) / scale`; prediction is `max(intercept + dot(coefficients, transformed_row), 0)`. There is no rounding, online fit, retry, fallback, or MA28 substitution.

`ridge_live_forecast` returns structured metadata including status, horizon, prediction, target/date range, T, model family/recipe/version/trainedAt/trainedDataVersion/dataCutoff, feature and promotion-policy versions, active status, dataVersion, and snapshotHash. It captures these from the same validated snapshot used by feature construction.

| Condition | Result |
|---|---|
| 1 day | `MODEL_NOT_APPROVED`, `PROMOTION_POLICY_FAILED`, null prediction/modelVersion; registry loader is not called. |
| 7/14 without ACTIVE | `MODEL_UNAVAILABLE`, null prediction; no fallback. |
| Missing 29-day history | `INSUFFICIENT_HISTORY`, null prediction. |
| Missing/inconsistent feature or snapshot | `FEATURE_UNAVAILABLE`, null prediction and safe reason code. |
| Registry/model integrity failure | `MODEL_UNAVAILABLE`, null prediction. |

Future cache identity is documented by a helper as business, scenario, SKU, horizon, T, dataVersion, snapshotHash and active model version. No cache is implemented in this phase.

## Focal validation and limits

`ml/tests/test_m6_10a32_live_ridge.py` is offline and synthetic. It uses `V3Dataset.feature_row` at the frozen historical cutoff as the feature reference and compares the safe scorer with manually parameterized sklearn `OneHotEncoder`, `StandardScaler`, and `Ridge.predict` fixtures for both 7d and 14d (absolute tolerance `1e-12`). No `.fit()` or TEST split is used. The fixture also exercises 7d ≤ 14d without modifying either prediction; this only proves the synthetic test bundle, **not** coherence of a future ACTIVE model pair. Since no production ACTIVE artifacts exist, actual 7d/14d bundle coherence is not confirmed.
