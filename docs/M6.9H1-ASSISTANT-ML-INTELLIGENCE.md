# M6.9H.1 — ML intelligence in the V3 assistant

## Scope

Expose explainable, read-only answers about the already approved V3 analytical methods through the existing assistant READ skills. This phase adds no skills, model training, artifacts, formulas, cloud behavior, or data writes. Tenant and scenario authorization continue through the existing authenticated context and service contracts.

## Reused skills and evidence

| Existing skill | ML question family | Evidence source and freshness |
| --- | --- | --- |
| `get_product_forecast` | Forecast method, HGB evaluation, features, WAPE, baseline, supervised-learning concepts | Existing evaluation contract. Operational forecast remains `MOVING_AVERAGE_28` for 1/7/14 days; HGB evaluation is historical evidence, not the production method. |
| `get_customer_intelligence` | K-Means clusters, cluster membership, silhouette, ARI, RFM comparison | Approved clustering artifact and authorized current-customer RFM for an individual assignment. Training cutoff is 2026-10-12; current assignment date is reported separately. |

| `get_cross_sell_recommendations` | FP-Growth, support, confidence, lift, association/causality | Frozen Market Basket artifact at 2026-10-12. Rules describe co-occurrence and do not establish causality. |
| `get_inventory_intelligence` | Explain that inventory measures are operational/descriptive, not ML | Existing inventory analytics; no new model or risk formula. |
| `get_supplier_intelligence` | Explain supplier metrics and absence of a quality score/model | Existing supplier aggregates; no “best supplier” score is created. |
| `get_business_health` | Existing composite health view, when requested | Existing authorized health contract; no arbitrary global score. |

Routing is deterministic and bounded to at most four READ skill calls per response. Overview questions gather the approved model families. Multi-intent queries reuse the same skills, preserve explicit entity/period scope where applicable, and ask for prioritization if the request cannot be represented safely. Frozen artifacts remain frozen; no operational sales are fed into model evaluation, clustering training, anomaly training, or Market Basket.

## Response and safety behavior

- User-facing answers/cards are assembled from validated contract fields; the assistant does not invent metrics, assignments, probabilities, or causal claims.
- Forecast evaluation reports HGB status and TEST WAPE/baseline when present while clearly distinguishing the approved MA28 operational method. Unsupported/missing evidence remains unavailable rather than being filled in.
- Customer clustering shows only artifact assignments or the existing authorized current-RFM assignment. Insufficient-history customers remain unassigned; Consumer Final is not treated as an individual.
- Sales anomalies are described as atypical behavior for contextual review, not fraud, confirmed incidents, or errors. Requested lists are capped at 20.
- FP-Growth support, confidence, lift, ticket evidence, and frozen cutoff are described as association evidence only.
- Inventory and supplier analytics are explicitly described as non-ML where asked; no new score is introduced.
- Public assistant history/trace does not expose internal skill arguments or hidden reasoning.
- The existing WRITE guard, preview, explicit confirmation, and cancellation protocol are unchanged. READ selection is not confirmation.
- No tenant IDs, lineage inputs, secrets, arbitrary ML parameters, or write controls were added to assistant skill arguments.
