# M6.9F.6B.2A — Wiring autenticado de analítica V3

## Alcance

Habilita en `/demand-forecast` vistas compactas de consumo de la API extendida V3. No implementa todavía el rediseño visual completo de F.6B.2. Las solicitudes son GET y se realizan en el navegador con el cliente Axios autenticado existente.

## Cliente y autenticación

- Reutiliza `apiClient` de `frontend/src/lib/api.ts`, el mismo cliente del Resumen, Predicción e Inventario.
- Conserva `NEXT_PUBLIC_API_URL`, interceptor `Authorization: Bearer …`, timeout, comportamiento de sesión y manejo global de 401.
- No lee el token desde los nuevos componentes, no registra headers, no agrega fetch con autenticación paralela y no comunica directamente con ML.
- Tenant, escenario y snapshot siguen determinados por el backend desde la identidad autenticada; la UI no envía `businessId`.

## Pestañas y llamadas

| Pestaña | Solicitudes |
|---|---|
| Resumen | `GET /api/intelligence/summary`, `GET /api/intelligence/inventory?limit=20` |
| Predicción | Rutas existentes de producto/forecast; sin cambio |
| Inventario | Inventario existente más `abcCounts`, `xyzCounts` y extensiones que el contrato entregue |
| Ventas | `GET /api/intelligence/sales?period=TODAY\|LAST_7_DAYS\|LAST_30_DAYS&includeSeries=true&compare=true&limit=10` |
| Clientes | `GET /api/intelligence/customers?limit=20&offset=0`; selección real llama `/customers/:customerRef` |
| Proveedores | `GET /api/intelligence/suppliers?period=…&limit=20&offset=0`; selección llama `/suppliers/:supplierRef` |
| Productos relacionados | `GET /api/intelligence/associations?limit=10&offset=0` y `/products/:sku/related?limit=10`; SKU elegido de filas reales del ranking cargado |
| Salud | `GET /api/intelligence/health?period=…&limit=5` |

Las rutas anteriores se expresan relativas al prefijo `/api`. Las funciones están tipadas con los contratos documentados en `M6.9F6B1-V3-BUSINESS-INTELLIGENCE-EXTENDED-API.md`. Resúmenes, tablas y detalles presentan el resultado del motor; React no recalcula RFM, riesgo, ABC/XYZ, métricas comerciales ni asociaciones.

## Estados

- `null` se presenta como “No disponible”; no se convierte en cero.
- Diferencia errores de acceso 401/403, entidad no encontrada 404, historial/contrato 422 y servicio no disponible 503. Las respuestas fallidas no conservan ni sustituyen datos por resultados de otro período.
- Listados vacíos son estados válidos con mensaje propio.
- Proveedor/costo/margen no disponibles conservan availability o null del contrato.
- Market Basket se rotula FROZEN con cutoff `2026-10-12`; el copy evita lenguaje causal.
- Salud enumera dominios sin score compuesto.

## Tests y validación local

- `test/businessIntelligenceExtended.api.test.ts`: verifica los nueve wrappers GET, parámetros y codificación de referencias; las funciones usan la instancia Axios compartida.
- `test/businessIntelligenceExtended.component.test.tsx`: nulabilidad de margen, selección de detalle mediante referencia retornada, estado vacío de asociaciones/relacionados, etiqueta congelada y error 503 sin fallback histórico.
- `test/businessIntelligenceDashboard.test.tsx`: regresión focal de Resumen, Predicción e Inventario.
- Suite focal: se ejecuta con `npx vitest run --config vitest.config.ts test/businessIntelligenceDashboard.test.tsx test/businessIntelligenceExtended.api.test.ts test/businessIntelligenceExtended.component.test.tsx` desde `frontend/`.
- El smoke cloud autenticado no forma parte de tests automáticos ni se da por aprobado por el build; requiere una sesión V3 existente.

## Pasos exactos para smoke cloud manual

1. Iniciar sesión normalmente en el negocio V3 y abrir `/demand-forecast`.
2. Abrir **Ventas**; comprobar Hoy, 7 días y 30 días, métricas, disponibilidad del margen y puntos de serie. Cero ventas es válido si el motor devuelve cero.
3. Abrir **Clientes**; verificar summary y segmentos, que Consumer Final no aparezca como fila RFM individual, y abrir el detalle seleccionando un cliente mostrado.
4. Abrir **Proveedores**; verificar gasto/órdenes y disponibilidad; abrir el detalle de una fila mostrada. Ausencias deben permanecer null/no disponibles.
5. Abrir **Productos relacionados**; comprobar estado FROZEN/cutoff 12 oct. 2026, reglas/evidencia y consultar un SKU real. Un resultado vacío es válido.
6. Abrir **Salud**; revisar freshness/status de dominios y ausencia de score global.
7. En **Inventario**, revisar risk counts y distribuciones ABC/XYZ/extensiones cuando estén presentes.
8. No crear ventas, compras, recepciones, clientes, proveedores ni cambios de stock. Si una llamada falla, registrar pestaña, status/código y mensaje seguro; no usar DevTools para copiar tokens.
