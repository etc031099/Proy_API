# M6.4 — Mongo local, coherencia y paridad Minimarket Pasco V3

## Resultado y límites

- Escenario: `minimarket-pasco-v3`; tenant operacional local reservado: `MINIMARKET-PASCO-V3`.
- Dataset: seed `2026`, corte `2026-10-12`, zona `America/Lima`, hash lógico `a90b913b6ee83174165b39eaab1526525b3aacc53cae1abe6c3f5a54a469cac8`.
- Mongo local: `inventory_billing`, replica set `rs0`, verificado `PRIMARY` en loopback. Importador/validator nunca leen `MONGODB_URI`; requieren `MONGODB_URI_DOCKER` conocido, validan host Docker local y lo convierten a `127.0.0.1:27017` con `directConnection=true`. Atlas SRV, otros hosts/puertos/bases abortan antes de escribir.
- No se conectó a Atlas, no se crearon usuarios, no se insertaron filas producto-día ni se entrenó ML. V1/V2 cloud no se consultaron.
- La carga usa upserts por claves estables en lotes, no una transacción única de 55,775 documentos (sería demasiado grande/larga). Cada documento/lote es reiniciable; `HistoricalScenario.status` permanece `importing` hasta pasar la paridad. El mismo hash terminado convierte la segunda ejecución en no-op. Otro hash requiere reset V3 explícito.

## Tiempo y consultas locales

`Transaction.date`/`InventoryMovement.occurredAt` conservan timestamps UTC; `localDate` conserva el día operacional de `America/Lima` y se usa para los smokes y los agregados mensuales. El validador canónico comprueba que timestamps y fechas Lima concuerdan. Al corte 2026-10-12 se encontraron: 13 ventas el 12/10, 34 el 11/10 y 206 en 06–12/10; 44 compras en los últimos 8 días y actividad en los últimos 30 días. Lookup por nombre humano, stock y productos bajo mínimo respondieron desde Mongo; también se calcularon top clientes y proveedores. Estos son conteos del dataset sintético, no actividad real.

`product-daily` permanece fuera de colecciones operacionales: 29,200 filas exactas siguen únicamente en el paquete/área de datos versionada por hash.

## Paridad lógica

`npm run v3:parity` compara filas canónicas (ordenadas por stable key) con sus proyecciones preservadas en Mongo, calcula hashes lógicos sin `_id`, timestamps técnicos ni metadata ambiental, valida los agregados, stock, relaciones, tenant scope y colecciones de soporte. Resultado: `CANONICAL_LOCAL_PARITY=PASS`; hashes por productos/contactos/transacciones/movimientos/auxiliares: PASS; hash aprobado: `a90b913b…cac8`.

## Tamaño local y capacidad Atlas

Paquete generado: **79,210,185 bytes** (~75.5 MiB). BSON V3 medido reconstruyendo los documentos importados: **100,391,226 bytes** (~95.7 MiB). Estimación comprimida atribuible a V3 prorrateando `storageSize`: **21,373,241 bytes**; índices atribuibles prorrateados: **9,685,285 bytes**; huella física aproximada V3: **31,058,526 bytes** (~29.6 MiB). La huella BSON + índices sin compresión es ~110,076,511 bytes. El prorrateo de almacenamiento/índices es aproximado, no una medición física exacta por tenant.

Después de la carga, Mongo local completo informa `dataSize=349,262,400`, `storageSize=72,388,608`, `totalIndexSize=97,996,800` bytes. Esto no revela la cuota/tier Atlas ni replica/backup overhead. **Atlas verdict: B — capacidad incierta** hasta medir cuota y consumo reales con información autorizada del cluster. No se conectó a Atlas y no debe cargarse V3 allí hasta pasar el gate de capacidad con reserva operativa.

## Comandos

Desde `backend/`:

```powershell
npm run validate:v3-definitions
npm run seed:v3:validate
npm run v3:import -- --local-docker
npm run v3:parity
npm test
```

El importador exige que `MONGODB_URI_DOCKER` de `backend/.env` apunte a la service DNS local `mongodb` y DB `inventory_billing`; crea su conexión exclusivamente a loopback. Nunca usa el `MONGODB_URI` por defecto. Reset opcional, solo si el hash del escenario cambia o se requiere reconstrucción autorizada:

```powershell
npm run v3:import -- --local-docker --reset --scenario-id minimarket-pasco-v3
```

Ese reset valida nuevamente loopback + PRIMARY y elimina exclusivamente documentos con `businessId=MINIMARKET-PASCO-V3` y `scenarioId=minimarket-pasco-v3` en las seis colecciones gestionadas; no acepta wildcard. Inventario es append-only para operaciones normales; el reset de simulación va directo a la colección Mongo bajo esta doble guarda local/exact-scope.
