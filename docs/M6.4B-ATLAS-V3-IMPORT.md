## Importador y recovery

`backend/scripts/import-minimarket-v3-atlas.js` adapta el importador M6.4 compartido: misma construcción de documentos, claves estables y paridad; solo cambia el target explícito. Mantiene local como valor por defecto, y Atlas requiere host/base exactos y confirmación. La conexión usa PRIMARY, máximo tres conexiones y `autoIndex/autoCreate=false`. Solo después del preflight/apply se inicializan los índices de la nueva colección auxiliar V3; los índices operacionales existentes se reutilizan.

Contactos preceden a productos para resolver proveedores; productos preceden a transacciones; transacciones preceden a movimientos. Offers están embebidas en Product. Claves SKU/productKey, SUP/CLI, saleCode/purchaseCode y eventos resuelven ObjectIds propios de Atlas. No se copia ningún ObjectId local ni se crea una cuenta de usuario V3: el schema operacional usa businessId lógico y el provisioning de la cuenta queda para la fase de aplicación.

Lotes de hasta 500 documentos: 1 contactos + 1 productos + 31 transacciones + 81 movimientos + 1 auxiliares = 115 lotes de datos. HistoricalScenario agrega el marcador de progreso/terminación. No hay transacción gigante. Un run propio `importing/failed` con hash aprobado puede reanudarse; un V3 inesperado o con otro hash se rechaza. Un run completado debe volver a superar paridad y retorna `alreadyImported=true` sin upserts.

Todas las escrituras se filtran por businessId V3 y scenarioId exactos. No se borran documentos durante la carga normal. Las 29,200 filas product-day siguen en el paquete canónico y no se duplican en Mongo operacional.

## Rollback preparado, no ejecutado

Solo ante una autorización específica para una carga corrupta:

```powershell

```

Revalida Atlas, base, tenant, scenario, marcador/hash y ausencia de referencias entrantes desde otros tenants. Elimina únicamente el filtro `{ businessId: 'MINIMARKET-PASCO-V3', scenarioId: 'minimarket-pasco-v3' }` en las seis colecciones gestionadas; verifica vacío y compara V1/V2 antes/después. No borra usuarios, integraciones, datos compartidos ni índices. No acepta wildcard ni un tenant diferente. La limpieza no es una transacción gigante y es reintentable si fue interrumpida.
