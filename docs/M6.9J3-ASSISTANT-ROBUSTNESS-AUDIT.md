# M6.9J.3 — Auditoría offline de robustez conversacional

Fecha: 2026-10-15. Base auditada: `0a29b501f0ca4b1cf4f72c36c6b98ddfdaee5ad7`.

## Evidencia y causa

El usuario observó en cloud que «de q equipo eres hincha?» terminaba en «No fue posible consultar el asistente.».

Reproducción local previa al fix, con transporte prohibido y catálogo simulado: `intent=ambiguous_query`, ninguna skill, un intento de clasificador genérico y `AGENT_PROVIDER_FAILED`. `domainGate.isOutOfDomain` no reconocía preferencias deportivas/casuales; V3 tampoco tenía un plan determinista para esa consulta. El orquestador llegaba a `classifyAgentIntent` del camino Gemini heredado.

Se localizaron los tres productores del texto genérico: el error interno del controlador HTTP, el constructor `AgentApiError` y el catch de la página del asistente. La UI agrupaba 400/401/403/500 y errores desconocidos, y el cliente descartaba los códigos seguros que no fueran de historial. Un 503 del mock previo **no reproduce** el mismo mensaje UI que un 500: por tanto, el status, código, excepción y configuración exactos del incidente cloud histórico quedan **NO CONFIRMADOS**. No se consultó producción ni se atribuyó el fallo a DeepSeek sin evidencia.

## Correcciones

1. Gate determinista ampliado para deportes, preferencias, saludos y otras consultas externas claras. Se conserva el escape para contexto explícito de negocio y las reglas temporales aprobadas. Los intentos de revelar secretos/instrucciones o saltarse confirmaciones reciben la respuesta de ámbito antes de seleccionar skills o acciones.
2. V3 conserva primero sus rutas deterministas existentes. Si ninguna entiende la solicitud, pide aclaración localmente; no envía una consulta desconocida al clasificador genérico heredado. V1/V2 mantienen su camino anterior.
3. Normalización acotada de abreviaturas `q`, `dl`, `d la`, `se ta`, `como tan`, `productos repongo` y sufijos `ps/pls/porfa`. No modifica números, SKU, nombres almacenados, umbrales ni fórmulas. «q compro esta semana» se resuelve como consulta de reposición, nunca como compra ejecutada.
4. «q producto se ta acabando» usa la lista global existente `low_stock`; no busca «producto se» como una marca. `should_reorder` continúa separado.
5. Una nueva solicitud explícita invalida la lista/pending de selección anterior, también al entrar a grounded u OUT_OF_DOMAIN. Un producto activo inequívoco permanece disponible entre dominios dentro del TTL existente. Las listas nuevas sustituyen las anteriores.
6. Configuración DeepSeek diferida hasta una síntesis real. Un cap/modelo/configuración inválidos no abortan la construcción del runtime para una consulta determinista/OOD; el intento grounded falla de forma controlada antes de llamar al transporte.
7. El controlador conserva `AGENT_INTERNAL_ERROR` y devuelve un mensaje técnico amigable, incluso ante un throw de `null` o un string. El catch anterior accedía a `error.code` sin contemplar `null`. La UI distingue petición inválida, acceso, proveedor, datos, límite, historial y fallo de red/servidor; solo usa códigos permitidos y nunca el mensaje bruto del servidor.

No se cambiaron skills, modelos, artefactos, datasets, contratos analíticos ni operaciones comerciales. Cross-sell sigue FROZEN al `2026-10-12`. El presupuesto DeepSeek permanece en 500 por defecto y máximo configurable 600, sin retry ni fallback automático a Gemini en la síntesis grounded.
