# M6.9D — UX conversacional de inteligencia V3

## Alcance

M6.9D presenta en el asistente resultados ya calculados por las siete skills READ de M6.9C. No añade motores analíticos, llamadas LLM, APIs de dominio, persistencia de acciones ni escrituras. El backend produce una proyección de presentación compacta (`v3Views`) junto al texto compatible existente; el frontend muestra tarjetas responsivas y conserva el texto como fallback de historial.

## Experiencia

- Ventas/negocio, inventario, pronóstico, compras conjuntas observadas, clientes, proveedores y salud usan vistas tipadas con métricas acotadas.
- Rankings muestran hasta cinco filas por vista. Las entidades seleccionables usan botones accesibles con nombre humano, identificador visible cuando aplica y selección por teclado/clic. Las recomendaciones cross-sell dejan seleccionar un producto y conservan el producto origen para el siguiente turno.
- Categorías también pueden seleccionarse para profundizar el ranking. El corte/periodo aparece como contexto compacto; el detalle de actividad y evidencia técnica existente no se reemplaza.
- La tarjeta de salud no crea una puntuación global. Cross-sell aclara que la asociación observada no prueba causalidad. Datos de contacto privados no forman parte de la proyección.
- Un horizonte de pronóstico no validado ofrece botones para 7 o 14 días y no presenta un pronóstico de 28 días.
- Si una lectura no tiene filas, la tarjeta indica ausencia de resultados sin construir cifras. Los errores de indisponibilidad usan lenguaje seguro y no exponen trazas internas.
- Elegir una entidad solo resuelve el contexto conversacional. Nunca confirma una compra, venta o alerta. Los botones Confirmar/Cancelar de una acción pendiente quedan deshabilitados durante otra petición o carga del historial.
- Las opciones, tarjetas y métricas se adaptan a móvil; las etiquetas conservan Unicode y se quiebran sin desbordar.

## Contrato y recorrido

El servidor agrega `v3Views` al sobre público del mensaje mediante una allowlist cerrada. El esquema contiene únicamente `kind`, título/subtítulo/nota, métricas primitivas y filas tipadas (`type`, `key`, etiquetas, métricas y mensaje opcional de selección). La proyección de historial persiste la misma forma acotada; no persiste documentos analíticos sin filtrar.

Recorrido:

1. M6.9C selecciona y ejecuta una skill V3 READ con el contexto autenticado existente.
2. `v3Routing` construye la proyección compacta usando su resultado y los nombres resueltos del escenario; conserva la respuesta textual y el contexto tipado.
3. El controlador expone solo campos explícitos; la vista React convierte cada fila seleccionable en un botón accesible.
4. La selección envía el identificador estable por el flujo conversacional normal. No llama al endpoint de decisión de PendingAction.

No se cambia el aislamiento existente tenant/usuario/conversación ni el límite de contexto/TTL de M6.9C.

## Compatibilidad y límites

- Contratos V1/V2 y texto del asistente permanecen compatibles; `v3Views` es opcional y aditivo.
- No se modifican frontend API, proveedor LLM, skills, fórmulas, forecast/artifacts, Mongo, Atlas, Render, Vercel, Telegram, Node-RED ni dispatcher.
- El formato es un resumen compacto; no intenta mostrar cada campo de analytics. El texto/actividad existentes siguen disponibles para evidencia detallada.
- La selección clickable es un atajo conversacional, no una autorización para mutar datos.
- Siguiente etapa sugerida: validación manual autenticada de los siete dominios en el escenario V3 después de la publicación correspondiente; esta fase no publica ni despliega.
