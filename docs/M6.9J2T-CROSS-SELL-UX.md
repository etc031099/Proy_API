# M6.9J.2T — Pulido UX de cross-sell

## Alcance

Se ajustó únicamente la presentación de `get_cross_sell_recommendations`. La resolución universal de productos J.2S, el routing, el servicio Market Basket, FP-Growth, sus artefactos y las acciones WRITE no cambiaron.

## Hallazgos

- Con una asociación, la respuesta ya mostraba el producto recomendado y la evidencia disponible.
- Con cero filas, quedaba un encabezado y una explicación técnica, sin decir con claridad que no había una regla disponible.
- La respuesta podía repetir dos explicaciones de FP-Growth con advertencias similares.

## Comportamiento final

- Una asociación: se presenta el producto base, el asociado y únicamente las métricas presentes en la respuesta de la skill (`ticketCount`, `support`, `confidence`, `lift` y estabilidad cuando estén disponibles).
- Varias asociaciones: se conserva el límite de visualización existente de cinco elementos; no se inventan productos ni métricas.
- Cero asociaciones con `available: true`: se indica explícitamente que el artefacto actual no ofrece una regla para el producto. Se aclara que esto no demuestra que nunca se compren juntos.
- `available: false`: se informa que no se pudo consultar una asociación validada, sin presentarlo como un resultado vacío válido.
- La explicación compacta aparece una vez: describe coocurrencias observadas, niega causalidad y garantía de ventas futuras, y mantiene el corte histórico congelado al `2026-10-12`.

El Market Basket permanece `FROZEN`; no se recalcula ni se actualiza. La consulta continúa por la skill READ existente, con cero llamadas LLM y cero tokens.

## Validación focal

`backend/test/v3Intelligence.test.js` cubre cinco casos J.2T y las regresiones de presentación/determinismo relacionadas:

1. una asociación con producto base y métricas observadas;
2. varias asociaciones respetando el límite de cinco;
3. cero asociaciones con mensaje explícito y sin alternativas inventadas;
4. indisponibilidad del artefacto diferenciada de un resultado vacío;
5. definición de `support` conservada junto a una sola advertencia metodológica, corte `2026-10-12` y uso determinista sin LLM/tokens.
