# M6.3 — Generador operacional de Minimarket Pasco V3

## Alcance y seguridad

Este generador construye un paquete de datos sintéticos local para `minimarket-pasco-v3`, versión `minimarket-pasco-v3-seed2026-v1`. No importa el paquete, no abre conexiones Mongo, no escribe en Atlas/V1/V2, no cambia servicios productivos y no entrena modelos. Los patrones de calendario, clientes y compras son supuestos de simulación; no describen observaciones reales de Pasco.

El catálogo M6.2 conserva sus 80 SKU comerciales independientes. Stock, demanda y reposición se simulan por SKU, nunca por marca agregada. El identificador lógico del negocio es `MINIMARKET-PASCO-V3`; no representa un tenant Mongo creado.

## Algoritmo

- Un PRNG Mulberry32 obtiene una semilla de SHA-256 por flujo (calendario, precios/costos, promociones, llegadas, cestas, clientes, estado, proveedor, retrasos). El flujo separado evita que un cambio de formato altere la demanda por acoplamiento de llamadas aleatorias.
- Las llegadas diarias siguen Gamma–Poisson (Negative Binomial con `shapeK` de M6.2); el multiplicador de calendario normaliza días de semana y aplica payday, fin de mes, feriados definidos y dos pulsos sintéticos anunciados. Cestas por misión y franja combinan perfiles de demanda, popularidad SKU, preferencias, tendencia gradual, precio/elasticidad, promociones, categoría y asociaciones probabilísticas.
- Clientes registrados se asignan según registro, perfil, frecuencia y actividad previa; el consumidor final anónimo permanece como grupo lógico y no se convierte en contacto. Cancelaciones/pending no mueven stock ni se cuentan como ventas completadas.
- Precios y ofertas cambian en fechas anunciadas. Las promociones usan templates M6.2, 5–15% de descuento, duración configurada y se descartan si el precio promocional no supera el mayor costo ofertado.
- Stock inicial usa la fórmula M6.1/M6.2 con límite de vida útil para perecibles. Las ventas registran demanda latente y venta efectiva; faltantes son `lostDemandSynthetic`, no ventas reales perdidas. El inventario rota FEFO, registra mermas por vencimiento y mantiene un ledger sin saldo negativo.
- Cada cierre revisa el punto de reposición, considera pedidos abiertos y demanda reciente, agrupa órdenes por proveedor/día, redondea por pack y recibe órdenes completas después del lead time. Costos de compra quedan congelados al ordenar; el costo contable del stock usa promedio ponderado. Retrasos normales dependen de los parámetros del proveedor; se seleccionan además entre 4 y 8 SKU no perecibles con retrasos controlados de 1–3 días para diversidad de escenarios.
- Se producen 365 filas por SKU con separación explícita entre variables conocidas al origen, resultados posteriores al día y targets. `unitsDemandedSynthetic`/`lostDemandSynthetic` son truth de simulación, no features. No se entrena ni exporta un modelo.

## Salida y determinismo

Formato NDJSON/JSON UTF-8, dinero en centavos enteros PEN, timestamps ISO UTC y `localDate` de negocio Lima. IDs son códigos lógicos estables; no hay ObjectIds ni referencias a un tenant real. Cada archivo de registros se canoniza con claves de objeto ordenadas; el manifest incorpora hashes SHA-256 por archivo, hash lógico, hash de configuración, rangos, cantidades medidas e integridad.

El destino predeterminado es `data/minimarket-pasco-v3/generated/`, excluido de Git porque el paquete es grande. El generador no sobrescribe destinos existentes: usar una carpeta nueva para cada regeneración o mover manualmente el paquete anterior después de verificar que es el artefacto propio.

Comandos desde `backend/`:

```powershell
npm run validate:v3-definitions
npm run seed:v3:generate
npm run seed:v3:validate
npm run seed:v3:generate -- --verify-reproducibility
```

Para escribir en otra ruta:

```powershell
npm run seed:v3:generate -- --output ..\data\minimarket-pasco-v3\generated-run-2
npm run seed:v3:validate -- --directory ..\data\minimarket-pasco-v3\generated-run-2
```

La opción de reproducibilidad genera dos carpetas temporales únicas, compara el hash lógico y elimina solo esas carpetas temporales propias.

## Auditoría

`seed:v3:validate` lee el paquete en streaming y revisa referencias de SKU/proveedor/cliente, claves estables, totales de venta y compra frente a sus líneas, fechas Lima, pedidos/recepciones, cantidades recibidas frente a movimientos, continuidad del ledger, saldo final por SKU, 365 días por SKU, 29,200 filas, demanda latente, promociones, hashes y límites de stockout. También calcula ventas por producto/categoría/mes/weekday, clientes y proveedores, promociones, slow movers, coocurrencias y readiness de forecast.

El JSON de `simulation-truth.json` mantiene parámetros latentes y retrasos controlados separados de las filas operativas. No debe pasarse como dataset de features.

## Resultados M6.3

Corrida aprobada con seed `2026`, rango `2025-10-13` a `2026-10-12` y negocio lógico `MINIMARKET-PASCO-V3`:

- 80 productos/SKU, 10 categorías, 42 subcategorías, 10 proveedores, 40 clientes y 103 ofertas.
- 12,815 tickets: 12,633 completados, 114 cancelados y 68 pendientes; 36,838 líneas de venta.
- 1,977 compras, 3,211 líneas de compra, 39,543 movimientos, 29,200 filas producto-día y snapshot final de 80 productos.
- 53,252 unidades completadas; ingresos de líneas `23,668,088` céntimos PEN; compras recibidas `17,906,199` céntimos PEN; demanda latente `4,813` unidades.
- El paquete ocupa 78,046,114 bytes. Hash lógico reproducible: `e37db04cdc0c4ae6db26e385091c709a139e3c9bd9682c37248a61ef8a8451eb`.
- `npm run seed:v3:generate -- --verify-reproducibility` produjo el mismo hash en dos corridas independientes. La validación integral devuelve `valid: true`, sin errores.

El reporte distingue llegadas al local, ventas completadas, cancelaciones y pendientes; las llegadas sin ninguna unidad disponible no se inventan como tickets de venta. La única advertencia de datos detectada corresponde a 1,415 días-producto con demanda latente no satisfecha: es truth sintético de simulación, no una medición de ventas reales perdidas.

Advertencias analíticas describen supuestos o censura sintética, no hechos de negocio. No se versionan los registros generados: se versionan generador, validador, comandos, tests y este resumen. M6.4 puede diseñar el importador idempotente; esta fase no carga la base.
