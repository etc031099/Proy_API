# M6.6A — Inventory Intelligence local ↔ Atlas

## Alcance y método

Verificación de solo lectura del escenario `minimarket-pasco-v3`, con corte fijo `2026-10-12` (`America/Lima`). Se ejecutó `InventoryIntelligenceV3.snapshot` dos veces, sin cambiar fórmulas ni parámetros: una con los registros operativos de Mongo local y otra con Atlas. Ambos usan el mismo bundle aprobado `MOVING_AVERAGE_28`, sus horizontes acumulados de 1/7/14 días y el mismo paquete canónico de producto-día. Este último permanece en el bundle validado; no se importa como colección operativa.

El lector `ml/scripts/m6_6a_read_mongo.js` limita conexiones a la base `inventory_billing`, valida local loopback o el host Atlas permitido, consulta PRIMARY y proyecta únicamente marcador de escenario, ledger de productos, compras/líneas y movimientos del escenario V3. No tiene operaciones de escritura. No imprime URI, credenciales ni documentos individuales. El driver `ml/scripts/m6_6a_inventory_parity.py` aplica el mismo snapshot y compara todos los campos de los 80 productos, distribuciones, rankings y hash lógico.

Tolerancia para números de punto flotante: diferencia absoluta máxima `1e-8`. Para SHA-256, los floats se redondean a 8 decimales y los objetos se serializan con claves ordenadas; metadatos de ambiente y runtime se excluyen. Las cantidades, categorías, flags, códigos de razón y ordenamientos se comparan exactamente.
