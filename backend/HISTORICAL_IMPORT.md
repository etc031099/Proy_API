# ML-PREP historical operational scenarios

ML-PREP prepares auditable operational history for later academic simulations. It
does not build ML features, train a model or expose import/reset over HTTP.

## NDJSON contract

The Python simulator will emit UTF-8 NDJSON: one causally ordered event per line.
Every event has `eventType`, a scenario-unique `eventId`, an explicit ISO-8601
`occurredAt`, and a `payload`. Supported events are:

- `contact.created`
- `product.created`
- `transaction.completed`
- `credit-payment.created`
- `transaction.cancelled`

Document references use explicit 24-character MongoDB ObjectIds generated by the
simulator. The importer always supplies `businessId` and `scenarioId` from its
command line, never from an event. Client prices and costs in transactions are
ignored: the existing backend rules obtain canonical values from `Product`.
Historical transactions provide an `exchangeRates` object keyed as `USD/PEN`
when conversion is needed. These rates are accepted only through the offline
context, making replay deterministic; normal HTTP requests still use the backend
exchange-rate service and cannot inject rates.

NDJSON was selected over a JSON array because it streams with constant memory and
allows checkpointing large 40k-250k scenarios. Parquet remains the correct format
for the multi-million-row ML dataset, but is not used as a MongoDB command stream.

```powershell
npm run import:historical-scenario -- `
  --file=../ml/data/operational/scenario.ndjson `
  --business-id=ACADEMIC_TENANT --scenario-id=demo-v1 --batch-size=500
```

Imports require a writable replica-set PRIMARY. A `(businessId, scenarioId)` marker
stores the source SHA-256 and progress. Repeating a completed import with the same
file is a no-op. A failed/changed scenario must be explicitly reset before retrying.
Each business operation uses a bounded MongoDB transaction; checkpoints are updated
per batch, so the complete input is never loaded into RAM.

## Safe reset and current-data backfill

Reset is restricted to the exact tenant and scenario and never calls
`dropDatabase`:

```powershell
npm run reset:historical-scenario -- `
  --business-id=ACADEMIC_TENANT --scenario-id=demo-v1 --confirm
```

Existing test products predate `InventoryMovement`. Do not backfill automatically.
After reviewing the tenant, create at most one opening movement from each current
positive stock with:

```powershell
npm run backfill:inventory-openings -- --business-id=TENANT --confirm
```

The command skips products that already have any movement and never invents a
transaction.
